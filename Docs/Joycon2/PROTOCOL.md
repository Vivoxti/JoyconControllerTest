# Joy-Con 2 по BLE — шпаргалка по протоколу

Конспект того, что нужно нам (кнопки, стики, LED, keep-alive). Протокол реверснут сообществом,
не официальный. Полный первоисточник и детали (IMU, вибрация, bonding, аудио):
<https://github.com/loserkidsblink/switch2mac/blob/main/research/PROTOCOL.md>
(на основе <https://github.com/ndeadly/switch2_controller_research>).
Минимальный рабочий пример на Web Bluetooth: `mascii/joy-con-2-web-bluetooth-api-demo`, `src/App.vue`.

Всё ниже — **проверить на нашем железе** (Фаза 0/1 в [PLAN.md](PLAN.md)) и при расхождении
поправить здесь.

## Обнаружение

| Что | Значение |
|---|---|
| BLE manufacturer company id | `0x0553` |
| Vendor id (внутри manufacturer data) | `0x057E` |
| PID Joy-Con 2 (R) | `0x2066` |
| PID Joy-Con 2 (L) | `0x2067` |
| PID Pro Controller 2 / NSO GameCube | `0x2069` / `0x2073` |
| Имя при рекламе | `Joy-Con 2 (L)` / `Joy-Con 2 (R)` (может быть кастомным) |

Manufacturer data (байты *после* 2-байтного company id): `[3..4]` VID LE, `[5..6]` PID LE,
`[10..15]` адрес хоста для переподключения (все нули = режим спаривания, зажат SYNC).

Фильтр Web Bluetooth (Chrome): `companyIdentifier: 0x0553`, `dataPrefix: 00 00 00 00 00 <PID LE>`,
`mask: 00 00 00 00 00 FF FF` → L: `67 20`, R: `66 20`. Bluefy фильтр по manufacturer data
не поддерживает — фильтровать по имени.

Подключаться к контроллеру можно, только пока мигают индикаторы (SYNC зажат).

## GATT

Сервис Nintendo: `ab7de9be-89fe-49ad-828f-118f09df7fd0`

| Назначение | Характеристика | Тип |
|---|---|---|
| Input report | `ab7de9be-89fe-49ad-828f-118f09df7fd2` | notify |
| Команды | `649d4ac9-8eb7-4e6c-af44-1ea54fe5f005` | write without response |
| Ответы на команды | `c765a961-d9d8-4d36-a20a-5315b111836a` | notify |
| Вибрация Joy-Con R | `fa19b0fb-cd1f-46a7-84a1-bbb09e00c149` | write without response |
| Вибрация Joy-Con L | `289326cb-a471-485d-a8f4-240c14f18241` | write without response |

- **Без SMP pairing / шифрования.** Попытка спаривания на уровне ОС — контроллер рвёт связь.
- Все записи — Write Without Response.
- Открытый вопрос: в каком сервисе лежат vibration-характеристики (важно для `optionalServices`).

## Формат команды

8-байтный заголовок + payload:

```
[0] command id   [1] 0x91   [2] 0x01 (BLE)   [3] subcommand
[4] 0x00         [5] payload length          [6] 0x00   [7] 0x00
[8..] payload
```

Ответ приходит на characteristic «ответы»: `[0]` = command id, `[1]` = `0x01` при успехе, данные с `[8]`.

| Cmd/Sub | Что | Payload |
|---|---|---|
| `0x09/0x07` | Player LED | `pattern 00 00 00` (4-бит маска; P1 `0x01`, P2 `0x03`, P3 `0x07`, P4 `0x0F`) |
| `0x0C/0x02` | Задать feature mask | `flags 00 00 00` |
| `0x0C/0x04` | Включить feature mask | `flags 00 00 00` |
| `0x02/0x04` | Чтение памяти | `len 7E 00 00 addr(4 LE)`, len ≤ `0x4F` |

Feature flags: `0x01` кнопки, `0x02` стики, `0x04` IMU, `0x10` оптическая мышь (только Joy-Con 2),
`0x20` ток батареи, `0x80` магнитометр. Для Joy-Con рекомендуют `0xB7`; для MVP хватит `0x03`.
**Не `0xFF`** — даёт фантомные ZL/ZR. (Web-демо шлёт `0xFF` — не повторять.)

Адреса памяти: `0x00013000` info-блок (серийник, VID/PID, цвета); `0x000130A8` factory-калибровка
стика 1; `0x001FC042` user-калибровка стика 1 (`FF FF FF` = не задана → брать factory).

## Handshake

Надёжный порядок:

1. Connect (без SMP).
2. Подписка на «ответы на команды» (до любых команд).
3. Чтение info-блока.
4. Чтение калибровки стика 1 (user → fallback factory).
5. Player LED.
6. Feature mask: `0x0C/0x02`, затем `0x0C/0x04`.
7. Подписка на input report.

Минимум (так делает web-демо, и это работает): LED → mask set → mask enable → подписка на input,
с паузами между записями.

**Keep-alive:** на macOS связь молча рвётся через ~10–17 c после последней *записи* хоста.
Повторять безобидную команду (тот же LED) раз в секунду. На Windows/Linux не требуется, но делаем
везде — дёшево.

## Input report (63–64 байта, ~60+ Гц)

| Offset | Размер | Поле |
|---|---|---|
| `0x00` | 4 LE | timestamp / счётчик |
| `0x04` | 4 LE | кнопки (битовая маска ниже) |
| `0x0A` | 3 | стик 1 (упакованная пара 12 бит) — тут стик **левого** Joy-Con |
| `0x0D` | 3 | стик 2 — тут стик **правого** Joy-Con |
| `0x10`/`0x12` | 2+2 LE | оптическая мышь X/Y (абсолютные, переполнение по 2¹⁶) |
| `0x1F` | 2 LE | напряжение батареи, мВ |
| `0x30` | 6 | акселерометр X/Y/Z (3× int16 LE) |
| `0x36` | 6 | гироскоп X/Y/Z (3× int16 LE) |

Стик: 3 байта → 24-бит LE; младшие 12 бит = X, старшие 12 = Y, диапазон 0–4095.

**Квирк правого Joy-Con:** стик приходит во *втором* поле (`0x0D`), а калибровка у него — в слоте
*стика 1*. Калибровать правый стик калибровкой стика 2 → мёртвая ось.

Калибровка (11 байт): центр, max, min — по упакованной паре 12 бит. `v = raw − center`;
положительная сторона делится на `max`, отрицательная на `min`; clamp ±1.

### Кнопки (`0x04`, uint32 LE)

| Бит | Кнопка | Бит | Кнопка | Бит | Кнопка |
|---|---|---|---|---|---|
| `0x00000001` | Y | `0x00000100` | Minus | `0x00010000` | D-Down |
| `0x00000002` | X | `0x00000200` | Plus | `0x00020000` | D-Up |
| `0x00000004` | B | `0x00000400` | R-stick | `0x00040000` | D-Right |
| `0x00000008` | A | `0x00000800` | L-stick | `0x00080000` | D-Left |
| `0x00000010` | SR (R) | `0x00001000` | Home | `0x00100000` | SL (L) |
| `0x00000020` | SL (R) | `0x00002000` | Capture | `0x00200000` | SR (L) |
| `0x00000040` | R | `0x00004000` | C | `0x00400000` | L |
| `0x00000080` | ZR | | | `0x00800000` | ZL |

## Платформенные заметки

- **Windows:** не спаривать через «Параметры». WinRT: `GattSession.MaintainConnection = true`.
- **macOS:** keep-alive 1 Гц; потолок ~66 Гц (connection interval не управляется).
  `NSBluetoothAlwaysUsageDescription`.
- **Android:** `requestMtu(517)` до подписки (иначе нотификации режутся до 20 байт); GATT-операции
  строго по одной.
- **Web:** HTTPS/localhost, `requestDevice` только из жеста пользователя, один chooser = одно
  устройство, reload рвёт соединение.
